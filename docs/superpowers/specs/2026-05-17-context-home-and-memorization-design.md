# Munajat — Contextual home & memorization pivot

**Date:** 2026-05-17
**Status:** Approved design — ready for implementation plan
**Author:** Achraf Trabelsi (with Claude Code)
**Driver:** Address App Store rejection 4.3(a) Spam (2026-05-13) by changing what the app *fundamentally does*, not by adding cosmetic differentiation.

## 1. Context

Munajat 1.0 was rejected under guideline 4.3(a) on 2026-05-13: "shares a similar binary, metadata, and/or concept as apps submitted to the App Store by other developers." A polite Resolution Center appeal on 2026-05-14 received a boilerplate refusal on 2026-05-15.

Diagnosis: in 3 minutes of review, the app looks like every other Hisn al-Muslim template — a grid of time-of-day categories, each containing a list of dhikr with a counter and audio button. Existing differentiators (widget, streak, share-as-image, RTL, Liquid Glass, Amiri Quran typography) are either invisible during quick review or decorative around the same core structure.

This spec describes a **substance-level pivot**: two new features that change the app's identity from "adhkar reference list" to "contextual companion with built-in memorization."

## 2. Goals

- Make the app visually and functionally distinct from any other adhkar app in the first 3 minutes of review.
- Add real, lasting value for end users — not feature-bloat for review purposes.
- Ship as build 2 of the same 1.0.0 version (no version bump, no scope expansion to macOS/visionOS — that stays on the v1.1 roadmap).
- Preserve all existing data, settings, and progress on update.

## 3. Non-goals

- Apple Watch companion (out of scope; would be v1.1 or later).
- macOS / visionOS App Store distribution (deferred to v1.1 per `v1-1-multiplatform-release` memory).
- Scholarly hadith/explanation layer per dhikr (future version).
- Audio recognition or pronunciation coaching.
- Social features, family sharing, cross-device sync.

## 4. Feature A — Contextual mode ("How do you feel?")

### 4.1 Concept

Replace the time-of-day-only mental model with an additional **life-state entry point**. A user can open the app, indicate what they're going through (anxious, grateful, sick, in conflict, before an important moment, etc.), and receive 3–7 curated dhikr from the Quran and Sunnah relevant to that state.

The classic categorical browse (morning / evening / sleep / etc.) stays — it's how returning users with daily routines will keep using the app. The contextual entry is the **new headline** of the home.

### 4.2 Taxonomy — 15 contexts in 2 families

**Emotions (8):**
- Anxious
- Grateful
- Sad
- Angry
- Fearful
- Happy
- Regretful / repentant
- Hopeful

**Life trials (7):**
- Sick
- Mourning
- Debt / financial distress
- Before an important moment (exam, interview, meeting)
- In conflict with someone
- Insomniac
- Doubting

Final wording, intro sentences, and icon mapping are part of the curation work (Phase 3).

### 4.4 Data — `contexts.json`

New bundled resource at `Adhkar/Resources/contexts.json`, manually curated and **not** regenerated by `scripts/build_adhkar.py` (to preserve curation across content refreshes).

Schema:

```json
{
  "version": 1,
  "contexts": [
    {
      "id": "anxious",
      "family": "emotion",
      "iconName": "wind",
      "color": "blue",
      "title": { "fr": "Anxieux", "en": "Anxious", "ar": "قلق" },
      "intro": {
        "fr": "Quand l'inquiétude pèse…",
        "en": "When worry weighs on you…",
        "ar": "حين يثقل الهمّ…"
      },
      "dhikrIds": ["abu_hurayrah_dhikr_3", "morning_05", "sayyidul_istighfar"]
    }
  ]
}
```

- `id`: kebab-case, stable across versions (used in deep links if needed later).
- `family`: `"emotion"` or `"trial"` — drives sectioning in the picker.
- `iconName`: SF Symbol name.
- `color`: secondary accent for the context header circle only — primary tint stays `.orange`.
- `title`, `intro`: localized strings via the existing `LocalizedText` mechanism.
- `dhikrIds`: 3 to 7 references to existing `Adhkar.id` values (already globally unique since `DhikrProgress.itemId` is `@Attribute(.unique)`).

### 4.5 `AdhkarDetailsView` — single-item mode

Today `AdhkarDetailsView` takes an `AdhkarCategory` and presents its dhikr list with `TabView` pagination. We add an alternative init:

```swift
init(adhkar: AdhkarCategory, focusedItemId: String? = nil, navTitleOverride: LocalizedText? = nil)
```

When `focusedItemId` is non-nil:

- `TabView` is replaced by a single `DhikrPageView` for that item — no swipe between siblings.
- Nav title becomes `navTitleOverride` (the parent context title) if provided.
- Completion overlay does not fire (no `category completed` semantics).
- Toolbar reset (clears `DhikrProgress` counter) remains active — counters are per-itemId, independent of how you arrived.

Counter sharing is intentional: the same dhikr accessed from a category or a context shares its `DhikrProgress`. If a user has counted 33× "Subhan Allah" via the morning category and later opens it from the "Grateful" context, the count reflects the day's actual practice.

## 5. Feature B — Memorization mode ("Hifz")

### 5.1 Concept

Opt-in spaced repetition for any dhikr the user wants to memorize. Anki-like flow: prompt → reveal → 4-button self-rating → SM-2 simplified scheduling.

### 5.2 UX flow

**Opt-in: `MemorizeButton`** placed in `DhikrPageView`'s toolbar/footer alongside favorite, share, audio:

- Default state: `brain` SF Symbol + label "Mémoriser" → tap creates `HifzCard(itemId:)`, haptic `.sensoryFeedback(.success)`.
- Added state: `brain.fill` + label "Dans Hifz" → tap shows `.alert` confirming removal.
- Status read via `@Query` SwiftData filtered by `itemId`.

**Memorize tab — 5th tab** in `RootTabView`. Icon: `brain.head.profile`.

```
pour ajouter ta première carte.
```

Filled state:

Buttons are colored functionally (red/amber/green/blue, 15% bg opacity) — exception to the mono-tint orange brand because they're action-distinguishing, not decorative. Labels and delays are always shown for accessibility.

Delay labels under each button are **dynamic** — computed at render time by calling `HifzScheduler.previewIntervals(for: card, now: Date())`, which returns the four delays the algorithm would assign for this specific card given its current `reps`, `intervalDays`, and `easeFactor`. The example above shows the typical case for a card mid-learning. A genuinely new card would show `aujourd'hui · +1 j · +1 j · +4 j` instead.

**End-of-session summary** (5s, dismissable):
```

Prochaine séance :
demain, 2 cartes
```

Mini crescent-star animation (reuses `CrescentStarPattern` primitives, respects `accessibilityReduceMotion`).

### 5.3 Data — `HifzCard` SwiftData model

```swift
@Model
final class HifzCard {
    @Attribute(.unique) var itemId: String
    var addedAt: Date
    var lastReviewedAt: Date?
    var nextReviewAt: Date
    var intervalDays: Double
    var easeFactor: Double
    var reps: Int
    var lapses: Int
    var stage: HifzStage
}

enum HifzStage: String, Codable {
    case new        // never reviewed
    case learning   // reps < 3
    case anchored   // reps >= 3 AND intervalDays >= 14
}
```

Coexists with existing `DhikrProgress` and `DailyActivity` in the same `ModelContainer`.

### 5.4 Algorithm — `HifzScheduler` (simplified SM-2)

Pure logic, no UI dependency, fully unit-testable. Pseudo-code:

```swift
func schedule(card: HifzCard, button: ReviewButton, now: Date) {
    card.lastReviewedAt = now

    if card.reps == 0 {  // new card
        switch button {
        case .again:     card.intervalDays = 0;  card.nextReviewAt = now;             card.lapses += 1
        case .hard:      card.intervalDays = 1;  card.nextReviewAt = now + 1.day;     card.reps = 1
        case .good:      card.intervalDays = 1;  card.nextReviewAt = now + 1.day;     card.reps = 1
        case .easy:      card.intervalDays = 4;  card.nextReviewAt = now + 4.days;    card.reps = 1
        }
    } else {  // existing card
        switch button {
        case .again:
            card.intervalDays = 0
            card.nextReviewAt = now              // stays due today, re-enters this session
            card.easeFactor = max(1.3, card.easeFactor - 0.20)
            card.lapses += 1
            card.reps = 0
        case .hard:
            card.intervalDays *= 1.2
            card.easeFactor = max(1.3, card.easeFactor - 0.15)
            card.nextReviewAt = now + card.intervalDays.days
            card.reps += 1
        case .good:
            card.intervalDays *= card.easeFactor
            card.nextReviewAt = now + card.intervalDays.days
            card.reps += 1
        case .easy:
            card.intervalDays *= card.easeFactor * 1.3
            card.easeFactor += 0.15
            card.nextReviewAt = now + card.intervalDays.days
            card.reps += 1
        }
    }

    card.stage = recomputeStage(card)
}
```

Initial `easeFactor` = 2.5. Floor = 1.3. No ceiling (Easy can drive ease arbitrarily high for genuinely easy cards).

### 5.5 Notification

Add `.hifzReminder` slot to `NotificationManager`, alongside existing morning/evening slots. UI in `SettingsView` for on/off + time. Body computed at scheduling time as "X dhikr à réviser aujourd'hui". Rescheduled at midnight for the following day.

### 5.6 Widget integration

`StreakService` already writes to the App Group suite `group.com.tadevv.Munajat`. Add two keys:

- `hifz.dueToday` (Int) — cards due as of "now".
- `hifz.totalCards` (Int) — total HifzCard count.

`CurrentPeriodWidget` (medium size only) displays a small "X à réviser" badge under the streak row. Widget remains a UserDefaults reader — no SwiftData call from widget process. After each review session, host app calls `WidgetCenter.shared.reloadTimelines(ofKind: "CurrentPeriodWidget")`.

## 6. Cross-cutting concerns

### 6.1 Cross-platform (iOS / macOS / visionOS)

All existing constraints from `CLAUDE.md` apply to new code:

- No `import UIKit`.
- `.sensoryFeedback(.success, ...)` for haptic, not `UIImpactFeedbackGenerator`.
- `Color.cardBackground` from asset catalog, not `Color(.secondarySystemBackground)`.
- iOS-only modifiers (`.navigationBarTitleDisplayMode`, etc.) guarded with `#if os(iOS) || os(visionOS)`.
- `.presentationDetents`, `.sheet`, `.glassEffect` (iOS 26+) — guard `.glassEffect` with `#available`, others are universally available on supported deployment targets.

Widget Extension stays iOS-only; only its App Group keys change.

### 6.2 RTL (Arabic)

Recent commit `c724902` fixed RTL globally. New screens inherit:

- Picker grid flips naturally.
- Context header `HStack` flips icon ↔ text.
- Progress bar in review session fills right-to-left (correct for Arabic reading direction).
- 4-rating buttons grid (2×2) flips logically — "Encore" lands top-right in RTL.

### 6.3 Accessibility

- VoiceOver labels on all new interactive elements (carte Home, picker tiles, MemorizeButton, 4 rating buttons — labels include the SM-2 delay).
- Dynamic Type via `.font(.body)` / `.font(.title)`; Arabic text gets `.dynamicTypeSize(.medium ... .accessibility3)` bound to prevent overflow.
- Reduce motion respected on the end-of-session animation (same pattern as existing `CompletionOverlay`).
- Non-color cues on 4 rating buttons: each carries its text label + numeric delay, so colorblind users have full information.

### 6.4 Visual language

- Dark mode forced (existing `.preferredColorScheme(.dark)` on `RootTabView`).
- Primary tint `.orange` everywhere; per-context color is a localized accent on the context header circle only.
- `CrescentStarPattern` background applied to home and **context detail screen** only. Picker, Hifz tab, and review session stay quiet (`AdaptiveBackground(decorated: false)`).
- `Amiri-Regular` / `Amiri-Bold` for Arabic text in new screens. `AmiriQuran` only when the dhikr is a Quranic verse.
- Liquid Glass (iOS 26+): home context card and review "Reveal" button use `.glassEffect()` behind `#available` guard. Fallback: `Color.cardBackground`.

### 6.5 Testing

The repo currently has no test target. Phase 1 includes adding one via a new `scripts/setup_test_target.rb` (mirrors `scripts/setup_widget_target.rb`). Framework: **Swift Testing** (not XCTest).

Minimum coverage:
- `HifzScheduler`: all 8 scheduling paths (new × 4 buttons, existing × 4 buttons), ease-factor floor at 1.3, stage transitions (new → learning → anchored), `previewIntervals(for:now:)` matches the actual scheduled delays.
- `DataProvider`: `contexts.json` decoding (nominal + missing file + unknown dhikrIds — should not crash, should filter out gracefully).
- (Optional) `LifeContext` Codable round-trip.

## 9. Apple 4.3(a) counterargument

Diagnosis was that the original app, despite being well-built, looked visually indistinguishable from other Hisn al-Muslim templates in the first 3 minutes of review. This pivot makes the difference visible immediately:

1. **0–5s of review:** Home displays a prominent "Comment te sens-tu ?" card. No other adhkar app has this entry point.
2. **5–10s:** Tapping the card reveals 15 contexts grouped into Emotions / Life Trials. The mental model is no longer "moment of day" but "life state."
3. **Throughout review:** The tab bar shows a dedicated **"Mémoriser"** tab. Visible in the app chrome, not buried in a menu.
4. **Any dhikr page (~30s):** The "Mémoriser" button is a peer action next to favorite, share, and audio. Not hidden.
5. **App Review Notes:** Three concrete differentiators listed with one screenshot each:
   - "Organized by emotional state and life situation, not just time of day"
   - "Built-in spaced repetition memorization with SM-2 algorithm"
   - "Curated dhikr selection per life context — 75+ scholarly associations"

The factual claim becomes provable: this is structurally a different app from other Hisn al-Muslim submissions, not a re-skin.

## 10. Risks & mitigations

| Risk | Mitigation |
|------|-----------|
| Build 2 still rejected under 4.3(a) | Escalate to App Review Board (formal appeal channel, distinct from Resolution Center) with a 60s video demonstrating the 5 differentiators above. |
| Curation drift — dhikrIds in contexts.json become stale if adhkar.json regenerates with different IDs | `build_adhkar.py` uses stable ID generation (verified in current source). If ever changed, add a CI check that all `contexts.json` dhikrIds resolve in `adhkar.json`. |
| HifzScheduler bugs corrupt user progress | Pure logic + Swift Testing coverage of all 8 paths before any UI hooks. No silent migrations in v1. |
| 5th tab on macOS native looks cramped | macOS not in this submission. Cross-platform compile must still pass. Revisit tab layout in v1.1 plan. |
| Widget process can't read SwiftData (it can't) | Widget reads only App Group UserDefaults, never SwiftData. `StreakService` is the single writer. |
| Forgetting accessibility on new flows | Phase 2 and 4 exit criteria include a VoiceOver pass before phase close. |
